# Règles personnalisées pour Gemini / Antigravity

- **Génération systématique des messages de commit Git** : À la fin de chaque tâche, générer systématiquement un message de commit Git clair, structuré (au format Conventional Commits), détaillé et rédigé en français, résumant l'ensemble des modifications apportées au projet.
- **Proscription des styles inlines (CSS externe obligatoire)** : Ne jamais utiliser d'attributs `style="..."` dans les templates HTML (sauf contrainte technique absolue telle que les corps d'e-mails HTML). Toujours déporter le CSS dans des fichiers `.css` dédiés (ou exploiter les classes utilitaires existantes) afin de garantir un code propre, modulaire et maintenable.
- **Système de Couleurs & Cohérence des Entités Métier (Design System Belle Vitesse)** :
  - Respecter scrupuleusement la nomenclature et la palette sémantique du Design System sur l'ensemble du site (admin ERP et portails publics de signature) :
    * **Check-in (Retours)** : Bleu Océan (`--entity-checkin`: `#3B82F6`, bg: `#DBEAFE`, text: `#1E40AF`, icône Lucide: `package-check`).
    * **Check-out (Départs)** : Vert Forêt / Racing Green (`--entity-checkout`: `#15803D`, bg: `#DCFCE7`, text: `#14532D`, icône Lucide: `truck`).
    * **Tournages / Projets** : Ambre Chaud (`--entity-project`: `#F59E0B`, bg: `#FEF3C7`, text: `#B45309`, icône Lucide: `clapperboard`).
    * **Incidents / Dommages** : Rouge Carmin (`--entity-incident`: `#EF4444`, bg: `#FEE2E2`, text: `#991B1B`, icône Lucide: `wrench` / `alert-triangle`).
    * **Décharges (Waivers)** : Violet / Indigo (`--entity-waiver`: `#8B5CF6`, bg: `#EDE9FE`, text: `#5B21B6`, icône Lucide: `file-signature` / `shield`).
    * **Statuts transversaux** : Succès/Validé (`--status-success`: `#15803D`, bg: `#DCFCE7`, text: `#14532D`, icône Lucide: `circle-check`), Attention/Attente (`--status-warning`: `#F59E0B`, bg: `#FEF3C7`, text: `#B45309`, icône Lucide: `alert-triangle`), Danger/Critique (`--status-danger`: `#EF4444`, bg: `#FEE2E2`, text: `#991B1B`), Info/À venir (`--status-info`: `#3B82F6`, bg: `#DBEAFE`, text: `#1E40AF`, icône Lucide: `info`), Neutre/Archivé (`--status-neutral`: `#6B7280`, bg: `#F3F4F6`, text: `#374151`, icône Lucide: `minus-circle`).
  - **Cohérence des composants et utilitaires** :
    * Pour une même entité ou statut, synchroniser systématiquement la couleur du badge (`badge-pill`), de l'icône Lucide, de la puce de timeline, de la bordure (`.u-border-left-*`, `.u-border-*`) et des cartes KPI.
    * Ne jamais coder de couleurs hexadécimales en dur pour ces entités dans le HTML ou les styles spécifiques : toujours consommer les variables CSS `--entity-*` et `--status-*` ou les classes utilitaires dédiées (`.u-text-*`, `.u-bg-*`, `.u-bg-*-light`, `.u-border-left-*`).
    * Après toute modification de fichiers CSS, régénérer systématiquement les bundles avec `python3 scripts/build_bundles.py --force`.
- **Exclusion et masquage des pré-devis** : La section et les fonctionnalités de pré-devis / devis (`pre_quotes`) sont désactivées et masquées de l'interface utilisateur. Ne plus les prendre en compte, ne pas les afficher dans les vues (projets, hubs, listes), et ne pas chercher à les intégrer ou les étendre dans les futures implémentations de fonctionnalités.
- **Proscription du JavaScript inline (JS externe modulaire obligatoire)** : Ne jamais inclure de balises `<script>` contenant du code logique directement dans les templates HTML (sauf stricte nécessité d'injection de payload JSON non exécutable type `<script type="application/json">`). Toujours déporter le code JavaScript dans des fichiers `.js` modulaires dédiés sous `static/js/src/` (admin ou public), déclarés dans `scripts/build_bundles.py` et compilés dans les bundles statiques (`admin.bundle.js` ou `public.bundle.js`). Après toute modification de fichiers JS ou CSS, régénérer systématiquement les bundles avec `python3 scripts/build_bundles.py --force`.
- **Nettoyage Systématique des Tests en Base de Données (Isolation des Tests Unitaires)** : Lors de l'écriture ou de l'exécution de tests (unitaires, intégration, MCP ou scripts de validation), ne JAMAIS laisser de données de test résiduelles dans la base de données. Utiliser prioritairement des bases de test isolées en mémoire (`sqlite:///:memory:` via `FLASK_ENV=testing`), des transactions avec rollback (`db.session.rollback()`), ou nettoyer systématiquement et rigoureusement tous les enregistrements créés lors de tests (`tearDown` / suppression systématique des projets, décharges, véhicules, contacts, utilisateurs, logs temporaires, etc.) à l'issue de chaque test ou intervention.
