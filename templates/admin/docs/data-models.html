Modèles de Données

Le schéma de base de données est conçu pour garantir l'intégrité des données tout en restant flexible pour les futurs développements. Voici les entités principales définies dans models.py.

Entités Majeures

1. Projets (Project)

Le pivot central de l'application. Un projet lie une production, un client, des véhicules et des dates.

  • project_id : Identifiant unique BVPR-XXXX (généré aléatoirement).
  • status : État du projet (Planifié, En cours, Terminé, Annulé).
  • pilot_contact_id : Référence au pilote principal.
  • production_contact_id : Référence au chargé de production.
  • dop_contact_id : Référence au DOP (Directeur de la photo).
  • first_ac_contact_id : Référence au 1er assistant caméra.
  • key_grip_contact_id : Référence au chef machiniste.

2. Inspections (Check-in / Check-out)

Trace l'état physique des véhicules avant et après utilisation. Les données sont "gelées" lors de la signature via une archive JSON.

  • inspection_number : Référence unique (BVCO-XXXX ou BVCI-XXXX).
  • status : État du processus (À signer, Signé).
  • snapshot : Copie JSON immuable des points de contrôle au moment de la validation.

3. CGL & Règles de Sécurité

Le système repose sur deux documents contractuels distincts :

A. Conditions Générales de Location (CGL - CglWaiver)

Signées par le représentant légal de la société de production cliente (BVRA-XXXX). Elles régissent les conditions générales de location du matériel, les cautions et assurances RC Pro.

  • Identifiant : BVRA-XXXX.
  • Données clés : Représentant, SIRET, N° TVA intracommunautaire, adresse de facturation, lieu d'utilisation.
  • Pièces jointes : Attestation d'assurance RC Pro Production.

B. Règles de Sécurité Universelles (BVSR - SafetyRulesWaiver)

Signé individuellement par chaque intervenant sur le tournage (pilote, cadreur, chef machiniste, etc.) pour attester du respect des consignes de sécurité.

  • Identifiant : BVSR-XXXX.
  • Données clés : Nom, rôle sur plateau, e-mail, téléphone, date de naissance, n° de permis de conduire.
  • Pièces jointes : Attestations et justificatifs selon le rôle.

Standards de Nommage

Règle d'Or : Les noms de colonnes en base de données sont toujours en Anglais (snake_case) pour la cohérence avec SQLAlchemy. Les labels d'affichage utilisateur sont gérés via les dictionnaires de traduction ou Airtable.

Exemple de relation :

# Extrait de models.py
class Project(db.Model):
    id = db.Column(db.Integer, primary_key=True)
    project_id = db.Column(db.String(20), unique=True)
    name = db.Column(db.String(100), nullable=False)
    # Relation avec la production
    production_id = db.Column(db.Integer, db.ForeignKey('productions.id'))
    production = db.relationship('Production', backref='projects')

Synchronisation des Données

Les tables issues d'Airtable (vehicles, heads, etc.) possèdent un champ fields de type JSON contenant l'intégralité des données brutes, permettant une grande flexibilité sans migration de schéma fréquente.
