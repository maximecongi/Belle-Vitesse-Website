Synchronisation Airtable

Le module services/sync_airtable.py est le pont vital entre la base de gestion administrative (Airtable) et le moteur de rendu web (MySQL).

Mécanisme de Synchronisation

La synchronisation suit un mode "Overwrite" (Écrasement) pour garantir que MySQL est toujours le reflet exact d'Airtable pour les catégories suivantes :

  • Véhicules (Equipements motorisés)
  • Heads (Têtes stabilisées)
  • Grips Categories & Products (Accessoires de fixation)
  • Static Content (Traductions et textes fixes de l'UI)

Fréquence et Déclenchement

Type Méthode Cible
Automatique Webhook Airtable Dès modification d'un enregistrement
Planifié Scheduler (Tâches de fond) Rafraîchissement complet toutes les ~24h

Note sur l'interface

Il n'existe pas de bouton de synchronisation manuel dans l'interface administrative actuelle. Les données sont maintenues à jour de manière transparente par le serveur.

Structure Technique

Chaque ligne synchronisée contient :

  • id : L'ID Airtable original (ex: recXvY...).
  • createdTime : Date de création originale.
  • fields : Un champ JSON contenant toutes les colonnes d'Airtable indexées par leur nom (snake_case recommandé).

Exemple de code de synchro :

# services/sync_airtable.py
def sync_table(model, airtable_table_instance):
    records = airtable_table_instance.all()
    # 1. Clean local table
    model.query.delete()
    # 2. Add fresh records
    for r in records:
        new_row = model(
            id=r['id'], 
            createdTime=r['createdTime'], 
            fields=r['fields']
        )
        db.session.add(new_row)
    db.session.commit()

Cache Applicatif

Après chaque synchronisation réussie, le cache Redis/In-Memory est vidé (flush) pour forcer le rechargement des données fraîches sur le front-end public.
