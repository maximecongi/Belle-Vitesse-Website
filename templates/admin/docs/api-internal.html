Architecture API

La plateforme Belle Vitesse utilise deux couches d'API distinctes selon l'usage : une API administrative pour le tableau de bord et une API REST publique pour les intégrations externes.

Documentation Interactive (Swagger)

L'intégralité de l'API REST publique est documentée via l'interface Swagger UI. Elle permet de tester les endpoints, de consulter les schémas de données et les codes de réponse.

Accéder au Swagger API

1. API Administrative (Interne)

Ces points d'entrée sont utilisés par l'interface d'administration pour les mises à jour dynamiques (AJAX). Ils nécessitent une session active avec les rôles appropriés.

Méthode Route Usage
GET /admin/api/events Récupère les événements pour le calendrier du dashboard.
GET/POST /admin/api/checkouts/<id>/status Consulte ou modifie le statut d'un Check-out.
GET/POST /admin/api/checkins/<id>/status Consulte ou modifie le statut d'un Check-in.
POST /admin/api/vehicle-configs Enregistre la configuration des points de contrôle d'un véhicule.

2. API REST Publique

Cette API est conçue pour les intégrations externes (applications tierces, mobiles). Elle est versionnée et utilise une authentification par jeton JWT (Bearer).

  • Base URL : /api/v1
  • Authentification : Authorization: Bearer <JWT_TOKEN>

Archivage & Synchronisation kDrive

La gestion documentaire s'effectue directement via l'API REST kDrive Infomaniak intégrée de manière native. Lors de la création d'un projet ou de la finalisation d'un document contradictoire, les fichiers sont immédiatement structurés et archivés de façon résiliente.

  • Création d'arborescence projet : Déploiement automatique de la hiérarchie standard 1_SÉCURITÉ, 2_PRODUCTION, etc.
  • Bundles documentaires : Téléversement en arrière-plan du PDF scellé et de l'ensemble des pièces jointes associées.

Note Technique : Toutes les routes de l'API administrative sont définies dans routes/admin/api.py, tandis que l'API publique est structurée dans le blueprint api_v1 (voir static/docs/openapi.yaml).
