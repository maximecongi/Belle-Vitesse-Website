Scellement des Documents

Le système de scellement garantit l'intégrité de chaque document PDF généré (Check-ins, Check-outs, Waivers). Toute modification ultérieure du fichier rendrait le sceau invalide.

Mécanisme Technique

Le scellement repose sur une combinaison de hachage cryptographique et de code d'authentification de message (HMAC).

graph TD A[Génération du PDF] --> B[Calcul du Hash SHA-256 du fichier] B --> C[Récupération des métadonnées : ID, Date] C --> D[Génération du Sceau HMAC-SHA256] D --> E[Stockage en Base de Données] E --> F[Validation lors de la consultation]

1. Empreinte Numérique (SHA-256)

Dès qu'un PDF est généré, le serveur calcule son empreinte (hash) SHA-256. Cette empreinte est unique : un seul bit de différence dans le PDF produirait un hash totalement différent.

Colonne SQL : pdf_file_hash (VARCHAR 64)

2. Sceau HMAC

Le sceau est généré à l'aide d'une clé secrète (SIGNATURE_SECRET_KEY) connue uniquement du serveur. Il lie le hash du fichier aux données de l'enregistrement.

seal = hmac.new(
    key, 
    msg=f"{record_id}|{pdf_hash}|{timestamp}".encode(), 
    digestmod=sha256
).hexdigest()

Validation de l'Intégrité

Lorsqu'un administrateur consulte un document, le système effectue les vérifications suivantes :

  1. Vérification du fichier : Le hash SHA-256 du fichier sur le disque est comparé à celui stocké en base.
  2. Vérification du sceau : Le sceau est recalculé et comparé au sceau stocké pour s'assurer qu'aucune donnée de la base (ID, dates) n'a été altérée.

Alerte de Sécurité

Si la clé SIGNATURE_SECRET_KEY est modifiée dans l'environnement, tous les sceaux existants deviendront techniquement invalides (bien que les documents restent intègres).

Stockage

Les preuves de scellement sont stockées dans les tables de mapping des documents signés :

  • checkout_signed_documents
  • checkin_signed_documents
  • pilot_waiver_signed_documents
  • production_waiver_signed_documents
